# Modality and attention

The same job has different interaction costs across surfaces. Adapt to where
attention, state and control actually live; do not impose one platform's
grammar on all the others.

## Web, mobile and desktop

Browser users bring expectations about links, reload, back/forward, tabs and
sharing. Durable locations and recoverable drafts matter when a session can
disappear at any navigation. A modal suits a bounded interruption; a long,
branching task often needs a navigable place of its own.

Mobile use may involve one hand, intermittent attention, the software keyboard,
poor connectivity or an interrupted session. Prioritize reachable actions and
continuation. Desktop work may need simultaneous views, dense comparison,
keyboard commands and durable window state. Do not reduce desktop work to a
phone layout stretched across a window.

Across both, preserve object identity and selection when adapting panes,
navigation or window size. Gesture shortcuts supplement discoverable actions;
they should not be the only route to a consequential command.

## Voice and ambient interaction

Speech is transient and serial. Long option lists are hard to compare or
revisit; offer short choices and a persistent visual record when available.
Design interruption, correction and turn-taking explicitly. People talk over
the system, and a spoken “stop” carries no visible scope, so the product has to
make audible which work it stopped.

Ambient assistance competes with ongoing work. The value of a notification
depends on timing, relevance and an action the person can take. Silence after
a known background action can be confusing; repeated unchanged updates can be
equally disruptive. Private content spoken aloud has a different exposure
than the same content shown on a personal display.

## CLI, API and developer products

Evaluate first successful use and repeatable composition: how the caller finds
the entrypoint, supplies required context, interprets errors and handles a
partial operation. Consistent identity, pagination, filtering, status and
authentication matter more than a universal preference for nouns over verbs.

A resource hierarchy, operation-oriented RPC or focused command can each fit a
domain. Do not reshape the protocol to match a stylistic slogan. Interactive
guidance should not make unattended invocation impossible; machine output
should not require scraping human diagnostics.

Help, setup, examples and runtime errors are one journey. The shortest example
should produce a real useful result under stated prerequisites, not conceal
credentials, installation or asynchronous completion. Repeated-use friction
often comes from unstable defaults, conflicting environments or missing
recovery identity rather than from syntax.
