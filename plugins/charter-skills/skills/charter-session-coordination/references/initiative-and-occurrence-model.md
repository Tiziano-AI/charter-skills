# Modeling a dependency between sessions

An initiative is a desired outcome. A session or task, or an agent it
delegated to, is one line of execution that can contribute an artifact, a
decision, evidence or an effect to it. Grouping sessions by outcome does not
merge their identities, permissions, lifecycles or workspaces.

## Include a session for what it can still change

A session belongs in the coordination problem when it can change success, the
next valid action or a material exposure. A completed session may own the only
exact artifact needed for integration. A running session may be irrelevant
because its independent result cannot affect this decision.

A shared directory, a similar title, common technology, a pin, a timestamp or
a dirty checkout is not enough. The decisive question is relational: what
would another owner do differently if this session's state or result changed?

For a complex interaction, note for each session only what answers that
question: exact identity, purpose and current state, the objects and
destinations it can change, commands, delegates, watchers or external effects
still live, artifacts produced, the input or approval it is waiting for, and
who integrates its result. A self-starting objective or a queued follow-on
belongs here only when it changes a dependency.

## Direction and order come from the actual dependency

An implementation session and a documentation session may stay independent
until both define the same public field differently. The collision is the
field's meaning, not their shared repository. Choosing one contract resolves
it; it need not serialize every implementation and prose edit.

A shared prerequisite can unlock several paths; an operator's priority choice
may block only one. Compare those actual dependencies instead of ranking
relationship types. Coordinate coupled decisions together, and after an
intervention recheck the relationships it touched, not every session.

## Unknowns constrain particular dependencies

Unknown identity prevents targeting that session. Unknown write scope prevents
deciding that an overlap is safe. Unknown delivery limits the claim that
depends on it without showing rejection. Unknown terminality matters while a
late effect could still change the result or harm something.

These are different missing facts with different remedies. Name the smallest
observation that tells the live alternatives apart. An owner or recovery path
that can hold a bounded uncertainty lets the coordinator move on without
halting independent work.
